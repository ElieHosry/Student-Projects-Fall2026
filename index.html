How to read these pages

Each entry below is one student proposal, assessed against the module's 10 categories and filed under the category it matched. The verdict next to each entry is three-tier: ✅ Fit (approvable as proposed), 🔶 Fit with adjustments (the page lists the specific changes required — treat them as conditions for week-5 approval), or rejected (rejections are not listed here; see the rejected log below, which includes a reshaping hint for resubmission).

Open an assessment page to find: the proposal as submitted, web-verified product references, a one-column Core Tech Requirements table (including the category's purple requirement), platform/front-end/back-end boxes with the backend scope, and suggested M1/M2 goals — G1–G3 ⭐ fixed plus 3 picks from the category's goal pool, each with an expandable Tech & dependencies block tailored to this project. Accepted proposals also have a companion -goals folder with the two milestone goal workbooks (.xlsx) ready to hand to the team.

All of this is advisory — the instructor remains the approval gate. Conventions and symbols follow the main doc set (see its Terminology Guide and Appendices).
