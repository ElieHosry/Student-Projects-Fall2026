SGGotWhat? - Team02 (student proposal)

Assessment: 🔶 Fit with adjustments · Category: Social Media · Assessed: 2026-09-21 · Status: awaiting instructor approval

Proposal (as submitted): A crowdsourced discovery app helping Singaporeans find real hidden gems (quiet cafes, unexpected viewpoints), countering the "SG got what" stereotype. Users log spots and one-off events, validated by the community; a personalized recommendation engine and route planner surface what's worth seeing and plan a full day out. An Events page pairs Eventfinda-API listings with community-submitted niche pop-ups. Backend C++ services handle spatiotemporal search, trending and multi-stop transit route optimization in real time. Named technical features: a Trust & Validation pipeline (hard checks — GPS radius + accuracy, rate limiting, account age; soft checks — perceptual photo hashing, n-gram/Jaccard text similarity); a personalised recommendation engine (per-user affinity vectors + collaborative persona matching, a reserved share from adjacent clusters to avoid taste bubbles, clusters recomputed in a background loop); a spatiotemporal discovery index (custom C++ spatial index over spots/events with valid-time windows, distance blended with trending/personalisation, auto-expanding radius, zoom-based pin clustering); and a multimodal router + itinerary optimiser (C++ earliest-arrival over bus/MRT from LTA DataMall, plus a time-window orienteering metaheuristic that selects/orders stops to maximise value). Custom tool: a web-based moderation & content editor (review soft-check-flagged submissions side-by-side with the detected duplicate, create/edit spots & categories, tune ranking weights with a live preview of a test user's feed). Perf targets: nearby query <50 ms p95 at 10k spots; itinerary <2 s for 20 candidates; submission validation <500 ms; deterministic-for-seed recommendations.

Adjustments required for approval:

  • Clear the 2D gate with a custom-rendered data-display surface. A map built purely from a maps SDK plus native lists would miss the module's 2D requirement. Custom-render at least the map layer (your own pin-clustering, auto-expanding-radius ring, route polyline and trending/popularity styling) and/or the day-out itinerary visualization in OpenGL ES (GLSurfaceView) — the editor's live "feed re-sort" preview is another good candidate — rather than only a drop-in map widget and RecyclerViews.
  • Safety & privacy for user-submitted spots and photos. Keep the trust/validation pipeline as a graded surface and add report/block plus moderation of user photos before public listing; don't expose a submitter's precise identity/home or a private draft location. (Your hard/soft checks and moderation tool already cover most of this — make the user-facing safety controls explicit.)

(Not required, affirmed: LTA DataMall and the Eventfinda API are legitimately available data sources — good choice over scraping. Keep the spatial index, recommender, router and orienteering solver as the team's own load-bearing C++.)*

References:

  • Atlas Obscura — Wikipedia (crowdsourced catalogue of unusual/hidden places via user-generated + editorial content, plus local community experiences and events)
  • Foursquare City Guide — Wikipedia (local search-and-discovery with personalized recommendations from history, a community-edited venue database and user trust levels)
  • Citymapper — Wikipedia (multimodal public-transit journey planning with live timings across walk/bus/metro, built on open GTFS transit data)

How each requirement applies:

Platform fit: Main: Native mobile + Web browser on mobile — a location-first discovery app (map, nearby, on-the-go itineraries) on the phone (device: Pixel 9a); the web-based moderation/content editor and the C++ desktop benchmark build are the tools/dev vehicle. Extended: Firebase + Linux server set up by M2 (full use T2).
Front end: The map (custom pin-clustering, auto-expanding radius, route polyline, popularity styling), the personalised discovery feed, the events browse/filter page, the day-out itinerary view and member profiles (OpenGL ES for the custom map/itinerary surface). Languages: Web — HTML/JS/CSS + C++→WASM (Emscripten, SDL2/3, OpenGL ES) for the moderation tool & desktop benchmark build; Native — Kotlin Native Android UI + C++ via JNI (Android Studio); OpenGL ES in a GLSurfaceView where realtime 2D is needed (no SDL on native).
Back end: The C++ services — the spatiotemporal spatial index (distance × trending × personalisation), the recommender (affinity vectors + persona clustering, background recompute), the trust/validation pipeline (GPS/hash/text-sim), and the multimodal transit router + time-window orienteering solver (LTA DataMall) — plus a Firebase store for spots/events/profiles and an Eventfinda-API adapter. Languages: C++.
Backend scope: Local now, server-ready (T2) — Firebase for the crowdsourced DB; the Linux server seam set up & basic-tested by M2, full use in T2.
  • Loop and/or service: several load-bearing C++ services — an in-memory spatial index answering nearby queries under 50 ms p95 at 10k spots, an orienteering solver returning a ≤20-stop itinerary in under 2 s, a validation pass under 500 ms per submission, and a fixed-interval background loop recomputing persona clusters and trending without blocking requests (deterministic for a given seed, so the recommender is reproducibly testable).
  • Data-driven: spots/events (with valid-time windows), categories, affinity/persona vectors, ranking weights (distance/trending/personalisation/exploration) and validation thresholds are hot-reloadable JSON — the editor retunes ranking without recompiling.
  • 2D: the map (own clustering/radius/route/popularity rendering) and the itinerary/feed views are custom-rendered in OpenGL ES (see adjustment 1). 3D: not needed. Networking: Eventfinda + LTA DataMall API calls, Firebase sync of the crowdsourced DB, and push for trending/events.
  • Custom tool: the web-based moderation & content editor — review soft-check-flagged submissions beside the detected duplicate, create/edit spots & categories, and tune ranking weights with a live preview of a test user's feed.
  • External DB: Firebase for spots/events/profiles/trust. Auth ⏭️: accounts + trust level (account age is a validation input). Analytics ⏭️: engagement events feed trending and persona clustering.
