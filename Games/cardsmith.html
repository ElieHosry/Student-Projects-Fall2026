CardSmith (student proposal)

Assessment: ✅ Fit · Category: Games · Assessed: 2026-09-21 · Status: awaiting instructor approval

Proposal (as submitted): CardSmith is a fantasy-themed, single-player PvE card battler: players manipulate elemental cards to defeat enemies through resource management and combo-driven combat. Players manage Energy by choosing to play cards for their effects or discard them to generate resources, and combine cards from four elements (Fire, Water, Earth, Lightning) to discover Elemental Combinations that modify attacks. The game has linear level progression, adaptable enemy behaviours, deck customisation, a permanent card collection and upgrade systems. Designed for native mobile. Team: 6 CS + 1 Design + 2 Art. Named technical features: a debugging UI; adaptable enemy AI; haptic feedback; a combo-driven combat system. Load-bearing C++: a deterministic, turn-based C++ simulation loop running each fixed step, giving real-time feedback for animations and VFX. Tools: a combo-system editor (define/test/simulate combos), a toggleable in-game debug overlay (state inspector, combo logs), a haptic-pattern previewer (assign a haptic pattern to an event), and an enemy encounter editor (define enemy type, HP, AI behaviour, modifiers per encounter). Design features: elemental combo-driven combat; discard-to-Energy resource management; progressive PvE encounters with waves + unique enemy behaviours; and deck customisation + permanent collection + a Tech Tree.

References:

  • Slay the Spire on Steam (the benchmark single-player PvE deckbuilder: build a deck, chain card combos, fight structured encounters, and unlock permanent progression — the deckbuilder-PvE + permanent-collection precedent)
  • Monster Train on Steam (a strategic deckbuilder whose lifeblood is synergy/combos between cards and factions — the combo-discovery + deck-synergy precedent)
  • Magicka on Steam (a game built on combining elements — Fire, Water, Earth, Lightning and more — into new effects; the elemental-combination system precedent)

How each requirement applies:

Platform fit: Main: Native mobile (Native Android — the stated target, with haptic feedback; device: Pixel 9a) — the Native PC build is the development/tools vehicle (the combo editor, encounter editor, debug overlay and haptic previewer). Extended: Firebase + a Linux server the team sets up by M2 (full use T2) for accounts and the permanent collection / Tech-Tree persistence.
Front end: A 2D renderer for cards, the hand/board, enemies, the Energy/combo HUD and the elemental-combination VFX, plus card animations and the deck/collection/Tech-Tree screens; haptics paired to key events. Languages: Native — Kotlin Native Android UI + the C++ engine via JNI (Android Studio); OpenGL ES for the realtime 2D in a GLSurfaceView; Web/desktop — SDL2/3 + OpenGL ES for the PC dev/tools build.
Back end: The deterministic, turn-based C++ simulation loop (card play/discard, Energy, the combo resolver, the adaptable enemy AI, damage), driving animations/VFX/haptics; plus Firebase for accounts + permanent collection/Tech-Tree persistence. Languages: C++ (engine + sim); Firebase-backed services on the Extended tier.
Backend scope: Local now, server-ready (T2) — the accounts / collection / Tech-Tree seam set up & basic-tested by M2, full use in T2.
  • Loop and/or service: the C++ loop is load-bearing — each fixed step it resolves card plays/discards, the Energy economy, the elemental-combination combos and the adaptable enemy AI deterministically, then feeds animations, VFX and haptics.
  • Data-driven: cards, the four elements + their combination rules, enemy types/behaviours, encounters (type/HP/AI/modifiers) and the Tech-Tree are all data — a new card, combo or encounter is a data change (authored in the combo + encounter editors).
  • 2D: card/board/enemy rendering, card animations, the Energy/combo HUD, the elemental-combination VFX and the deck/collection/Tech-Tree screens (custom-rendered). 3D: not needed. Networking: single-player; the collection/Tech-Tree persistence is async client↔︎cloud (Application Communication ✅), so a Networking System is optional (🔵).
  • Custom tool: the combo-system editor (define/test/simulate combos) and the enemy encounter editor (type/HP/AI/modifiers) are content-authoring tools; the debug overlay (state inspector + combo logs) and the haptic-pattern previewer are strong dev tools.
  • External DB: accounts + the permanent card collection + Tech-Tree progression. Auth ⏭️: accounts for persistent progression. Analytics ⏭️: optional — combo usage / encounter win-rates for balancing.

Track Goals & Team Composition

Recommended composition: 6 CS + 1 Design + 2 Art (9) — matches the team's stated make-up. One designer owns the elemental-combination system, the discard-to-Energy economy, the deck/collection/Tech-Tree progression and the adaptable-AI/encounter difficulty design; two artists carry the card art (a fantasy elemental set), the enemy roster, the elemental-combination VFX and the deck/collection/Tech-Tree UI — a card game is art-forward (every card is a bespoke illustration), which justifies the two artists (rules: min 1 Design mandated, max 9 total, D+A ≤ 3; see team-formation.pdf). Scope note (advisory): a deterministic combo engine + adaptable AI + deck/collection/Tech-Tree + a combo editor + an encounter editor is a full but well-structured scope for a single designer — the elemental-combo combat with the discard-to-Energy loop, ~2 elements' worth of combos, a few encounters and the combo editor is the M1/M2 floor; all four elements, the full Tech-Tree and broad card variety are the stretch. With one designer, keep the card/combo/encounter balance tightly scoped.
