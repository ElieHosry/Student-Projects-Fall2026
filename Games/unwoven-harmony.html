Unwoven Harmony - Team21 (student proposal)

Assessment: ✅ Fit · Category: Games · Assessed: 2026-09-21 · Status: awaiting instructor approval

Proposal (as submitted): An action game where gesture-based combat (tap, press-and-hold, swipe) meets dynamic music inspired by Chinese mythology. Players cast elemental magic to defeat enemies and bosses across short, music-driven stages. Unlike traditional rhythm games, hitting the beat is optional but rewarding — you can clear a stage by mashing, but hitting on beat grants special finishing moves and extra visual/audio flair. The soundtrack fuses traditional Chinese instruments with modern electronic beats; before a stage, players customise a moveset by equipping up to three of the Five Elements, and can import their own music. Named technical features: JSON data serialization for easy reading/manual editing; in-built BPM recognition for custom tracks; enemy AI that conforms to the track's BPM; and server-side data handling to prevent cheating. Loop: a C++ game loop handling a large queue of gestures for player + enemy attacks/movesets. Tool: a music importer that lets users add their own music, automatically matching attacks to the beat. Design features: fullscreen gesture combat (tap/hold/swipe anywhere, mapped to the Five Elements — Wood, Fire, Earth, Metal, Water, each with unique properties); a combo system where on-beat inputs chain moves and build Qi Energy to trigger finishing moves (missing beats has no penalty); 5 linear PVE stages (~2 min each, 1–2 enemies at a time, some/all with a boss, clear before the timer, enemies spawn on fixed timers independent of the beat); and an ability-unlock system (progression + a post-stage shop where stage-earned currency buys moves, cosmetics and music tracks).

References:

  • Hi-Fi RUSH on Steam (the defining precedent: an action-combat game where everything syncs to the music and hitting the beat enhances your combos but is never required — exactly the "optional but rewarding" hook)
  • Metal: Hellsinger on Steam (on-beat attacks deal more damage and fill a Fury meter — the direct precedent for the on-beat-builds-Qi / finishing-move reward)
  • AudioSurf on Steam (a game built around importing your own music and auto-generating beat-timed gameplay from any track — the custom-music-import + BPM-analysis precedent)

How each requirement applies:

Platform fit: Main: Native mobile (fullscreen touch gesture combat + on-device music import suit a phone; device: Pixel 9a) — the Native PC build is the development/tools vehicle (the music-importer tool). Extended: Firebase + a Linux server the team sets up by M2 (full use T2) for the **server-side anti-cheat** data handling, accounts and the currency/unlock/leaderboard store.
Front end: A 2D renderer of the elemental combat (player, 1–2 enemies, bosses, per-element spell VFX), the fullscreen gesture-input layer, the Qi/combo/timer HUD and the beat/on-beat flair, plus the shop and music-import screens. Languages: Native — Kotlin Native Android UI + the C++ engine via JNI (Android Studio); OpenGL ES drawn in a GLSurfaceView for the realtime 2D; Web/desktop — SDL2/3 + OpenGL ES for the PC dev/tools build.
Back end: The C++ engine core (fixed-timestep loop over a large gesture queue for player + enemy movesets, the Five-Elements combat, the audio/BPM analysis feeding the combo/Qi and the BPM-conforming enemy AI) + a server-side data layer that validates progression/currency to prevent cheating. Languages: C++ (engine); Firebase-backed services on the Extended tier.
Backend scope: Local now, server-ready (T2) — the anti-cheat / accounts / store seam set up & basic-tested by M2, full use in T2.
  • Loop and/or service: the C++ loop is load-bearing — a fixed-timestep loop resolves a large queue of gestures into player and enemy moves, runs the Five-Elements combat, and drives the audio/BPM analysis that feeds the on-beat combo/Qi rewards and the BPM-conforming enemy behaviour.
  • Data-driven: moves, the Five Elements and their properties, enemy types/patterns, stage layouts and shop/unlock data are all JSON (easy to read and hand-edit), so a new move or enemy is a data change.
  • 2D: sprite/particle rendering of the elemental combat, spell VFX and the on-beat flair + HUD (custom-rendered). 3D: not needed. Networking: no real-time multiplayer; the anti-cheat / accounts / store calls are async client↔︎server (Application Communication ✅), so a real-time Networking System is optional (🔵).
  • Custom tool: the music importer — import a track, run BPM recognition, and auto-generate the beat map so the player's attacks and the enemy AI align to the imported song.
  • External DB: accounts, currency/unlocks/cosmetics and (server-validated) progression. Auth ⏭️: accounts for the anti-cheat store. Analytics ⏭️: optional — on-beat engagement and stage drop-off for tuning.

Audio note: audio here is load-bearing (the combat, combos and enemy AI all key off BPM/beat), so the BPM-recognition + adaptive-music tech is real CS work (M1G6 / M2G9), and the TEAM/Audio goals carry a sync clause (below).

Monetization note: the shop uses stage-earned currency for moves, cosmetics and tracks — progression, not pay-to-win. If real-money purchases are ever added, keep them to the module's clean-monetization rule (cosmetics/tracks only, no pay-to-win).

Track Goals & Team Composition

Team composition (set by instructor): 6 CS + 1 Design + 1 Art (8) — the Chinese-mythology setting, per-element spell VFX, the enemy/boss roster and the cosmetics are a large, VFX-forward art surface, which one artist now carries; a single designer owns the gesture-combat moveset design (Five Elements), the optional-rhythm combo/Qi system, the stage/enemy design and the shop economy (rules: min 1 Design mandated, max 9 total, D+A ≤ 3; see team-formation.pdf). Art-scope flag: a VFX-forward combat game is a heavy load for a single artist — prioritise the per-element spell VFX (the core reward, produced at M2A5) and the character/enemy roster + animation, keep the stage/UI art lean and reusable, and scope the roster/stages hard; if the art volume outgrows one artist, a 2nd artist would help within the D+A ≤ 3 cap. Scope note (advisory): gesture combat + BPM analysis + adaptive music + a music-import tool + Five-Elements movesets + 5 stages + bosses + a server anti-cheat store is a large surface — treat the gesture combat with ~2 elements, the beat clock + on-beat Qi reward, 2 stages and one boss as the M1/M2 floor, with all five elements, the music importer and the server store as the stretch. BPM detection quality is the key audio-facing risk — prototype it early.
