Planet Pawsitive (student proposal)

Assessment: ✅ Fit · Category: Games (gamified-app lens) · Assessed: 2026-09-22 · Status: awaiting instructor approval

Proposal (as submitted): Planet Pawsitive encourages Singaporeans to build a lasting habit of using the ReturnRight reverse-vending machines. It has a location-based tracker (nearest machine) and a Tamagotchi mini-game: each bottle deposited grants a token (used for feeding / drawing new tamagotchi), with the token amount determined by an uploaded image of the machine's return summary. The pet's state doubles as the reminder system (prompting returns without scheduled notifications); decorations + interactable objects for the pet's space are a stretch goal. The main interface reflects ongoing activity and surfaces context on Singapore's waste situation, and a lifetime tracker records total containers returned + deposits recovered. Named load-bearing C++ (local engine): the real-time interactive pet simulator + pet progression, the real-time pet growing synced to a world clock driving a day/evening/night room cycle, the custom Pet AI (random actions — sleeping/walking/sitting), and custom 2D technical art (light source, shaders) — all in C++. Named technical features: OCR image recognition (in Python) on the machine's confirmation screen, with a timer to prevent fraudulent use; the real-time pet growing + day/night world-clock sync; the custom Pet AI; and the custom 2D technical art (lighting/shaders). Tools: the OCR scan of return-summary images; and an accessories/decorations editor. Design features: the Tamagotchi pet system (emotional-responsibility lifestyle framing); the scan-to-track mechanic (photo → OCR reads container count → tokens); a habit-forming loop (streaks, cumulative bottles, pet-status nudges instead of notifications); and a "Semakau" clock (a Singapore-landfill countdown — "Your 5 bottles have stayed out of Semakau island!" / a countdown to 2035 — inspired by the Climate Clock). Team: 6 CS + 1 Design + 0 Art.

Note (category): like other gamified apps (there is no sustainability/health category), Planet Pawsitive is filed under Games and assessed through the gamified-app lens (pet/progression/habit-loop systems) — the same way the module treats step-and-pet and habit-loop projects. The recycling/awareness is the theme; the pet-habit loop is the product.

Note (module completeness): the app needs a backend + external DB (pet state, tokens, lifetime tracker, OCR results) — use Firebase and/or the team's Linux server (set the seam up + basic-test it by M2). Platform: location tracker + image upload → a mobile build (Native Android, Pixel 9a). On the Python OCR: the module's graded core is C++ — the pet sim / AI / day-night / technical art are correctly in C++; the Python OCR is fine as a backend/tool (like a backend script), but keep the load-bearing real-time logic in C++ and treat OCR as a service the app calls (with the anti-fraud timer server-checked). Monetization: none specified and the economy is earn-by-recycling (tokens), which is clean.

References:

  • Recycle N Save — Smart Reverse Vending Machines (Singapore) (the real Singapore scheme this app is built on: deposit drink containers at reverse-vending machines and earn rewards — the exact scan-a-deposit-earn-a-reward + Singapore-recycling context)
  • Tamagotchi — Wikipedia (the archetypal virtual pet you raise through life stages, where the pet's needs periodically remind you to care for it — the pet-as-reminder + care/growth precedent)
  • Climate Clock — Wikipedia (the countdown clock showing the time left to limit warming to 1.5°C — the team's stated inspiration for the "Semakau" landfill-countdown clock)

Track Goals & Team Composition

Recommended composition: 6 CS + 1 Design + 1 Art (8) — the proposed 6 CS + 1 Design + 0 Art is the module's tight case for an art-forward concept: a Tamagotchi pet with growth stages, day/night rooms, decorations and drawable/collectable tamagotchi is a real art surface, so with no artist the single designer must also carry the D11 conditional each milestone, and a solo designer + 0 artists is exactly what the design pool flags ("must ask the instructor which conditional bends", see design-goals-pool.pdf). Mitigating factor: the proposal's custom 2D technical art (lighting/shaders) is CS-generated, which offloads some of the visual polish onto the engine — but the pet, room and decoration assets still need an artist's hand. Recommended: add 1 Artist (best for the pet/room/decoration charm), or at least a 2nd designer so one owns the habit/economy design and the other absorbs the D11 art surface. If the team stays 0-artist, scope hard: one pet with a few growth stages + a small reusable decoration set authored under D11, and expect the instructor sign-off on the bent conditional. Scope note (advisory): a real-time pet engine + custom Pet AI + shader/lighting tech art + an OCR scan pipeline + a decorations editor is a solid scope — the pet sim + world-clock growth + day/night + the OCR-to-token scan + one decoration is the M1/M2 floor; the advanced lighting/shaders, the interactable-objects editor and the full Semakau-clock + habit-loop polish are the stretch. OCR reliability + anti-fraud is the trickiest bit — validate the scan pipeline early with real machine-summary photos, and check the anti-fraud timer server-side.
