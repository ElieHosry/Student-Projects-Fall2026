Orbital Waddle (student proposal)

Assessment: ✅ Fit · Category: Games · Assessed: 2026-09-21 · Status: awaiting instructor approval

Proposal (as submitted): You play an astronaut penguin whose partner is kidnapped by the Astrorca and taken to Planet 67. Journeying across a chain of alien planets — each a rotating isometric cube world — you clear timed enemy waves to earn the key and locate a hidden Thingamajig to power the rocket onward. Combat is hack-and-slash roguelite (in the vein of Hades / Megabonk): start with a snowball launcher, grow an arsenal of weapons, upgrades, abilities and stat boosts. Each planet has its own terrain, enemy mix and theme, and walking off an edge smoothly rotates the whole world so a new cube face becomes the ground. Named technical features: (1) a planet-rotation traversal engine that reorients terrain + the gravity vector as the player crosses an edge while keeping every active enemy/projectile/object stable in the local frame; (2) an ECS sustaining 100 concurrent enemies per wave without frame drops on Android; (3) a Thingamajig relocation system that updates a HUD compass; (4) a data-driven weapon/ability/stat economy backed by a Firebase layer for cloud-save sync, server-side achievement unlocks and a server-validated global leaderboard. Loop: the game loop, ECS, planet rotation and enemy AI run in one fixed-timestep C++ loop (Android Studio + C++ via JNI) targeting 100 live enemies; adding an enemy/wave is a data change. Tools: a planet & wave editor (terrain, spawn zones, Thingamajig points), a data-driven config tool (weapon stats, upgrade trees, enemy params, post-rescue difficulty tiers), and a CI pipeline. Design: the rotating planet world; a 5-enemy roster (Astrorca, RoboLi Seals, Space Petrels, F.O.X, Polaroids) with distinct movement/attack patterns; a wave→key + Thingamajig loop across 4 planets (3 themed + Planet 67 finale); and a New Game+ completionist loop with remixed waves and cosmetic-only rewards (no pay-to-win). Platform: Mobile, native Android.

References:

  • Hades on Steam (the hack-and-slash roguelite the proposal names: escape-run structure, a growing arsenal of weapons and stackable Boons/upgrades, thousands of build combinations, isometric combat — the roguelite arsenal + New Game+ precedent)
  • Fez — Wikipedia (a world you traverse by rotating between faces, so a different plane becomes navigable ground — the closest published precedent for the cube-face rotation-traversal mechanic)
  • Super Mario Galaxy — Wikipedia (small self-contained planetoids with all-around gravity that let you walk around a body as its gravity reorients — the planet-gravity-reorientation precedent)

How each requirement applies:

Platform fit: Main: Native mobile (Native Android — the stated platform, Android Studio + C++ via JNI; device: Pixel 9a) — a touch roguelite with an on-screen HUD compass; the Native PC build is the development/tools vehicle (the planet/wave editor + config tool). Extended: Firebase + a Linux server the team sets up by M2 (full use T2) for cloud-save sync, server-side achievement unlocks and the server-validated global leaderboard.
Front end: An isometric renderer of the cube-world planet (terrain, the penguin, up to ~100 enemies, projectiles and VFX) with the **smooth edge-crossing world rotation**, the wave/health/arsenal HUD and the Thingamajig compass. Languages: Native — Kotlin Native Android UI + the C++ engine via JNI (Android Studio); OpenGL ES drawn in a GLSurfaceView for the realtime isometric world (the rotation is a 3D transform of the camera/world); Web/desktop — SDL2/3 + OpenGL ES for the PC dev/tools build.
Back end: One fixed-timestep C++ loop running the ECS (≥100 enemies/wave), the planet-rotation traversal (terrain + gravity-vector reorientation, keeping entities stable in the local frame), enemy AI, the wave→key→Thingamajig progression and the weapon/ability/stat economy + a Firebase application-communication layer. Languages: C++ (engine via JNI); Firebase-backed services on the Extended tier.
Backend scope: Local now, server-ready (T2) — Firebase cloud-save / achievements / leaderboard seam set up & basic-tested by M2, full use in T2.
  • Loop and/or service: the C++ loop is heavily load-bearing — one fixed-timestep loop drives the ECS at a target of 100 concurrent enemies/wave on Android, the planet-rotation reorientation (terrain + gravity vector, entities stable in the local frame), enemy AI, waves and the arsenal economy.
  • Data-driven: the ECS separates data from behaviour — enemy types, wave patterns, weapon/upgrade/stat trees, per-planet terrain/theme and the post-rescue difficulty tiers are all data, so a new enemy or wave is a data change, authored via the editor/config tools.
  • 2D: isometric sprite/tile rendering of the cube-face world, enemies, projectiles, VFX and the HUD compass (custom-rendered). 3D: 🔵 the edge-crossing rotation and gravity reorientation are a 3D camera/world transform layer over the isometric art — a strong-students concern, not a full 3D pipeline. Networking: no real-time multiplayer; the Firebase cloud-save / achievement / leaderboard calls are async client↔︎service (Application Communication ✅), so a real-time Networking System is optional (🔵).
  • Custom tool: a planet & wave editor (terrain, enemy spawn zones, Thingamajig relocation points per planet) and a data-driven config tool (weapon stats, upgrade trees, enemy params, difficulty tiers) — rebalance without recompiling.
  • External DB: Firebase cloud saves, achievements and the global leaderboard. Auth ⏭️: accounts for cloud save. Analytics ⏭️: optional — wave/death/build telemetry for balancing.

Track Goals & Team Composition

Recommended composition: 6 CS + 1 Design + 2 Art (9) — four distinct planet themes, a 5-enemy roster + the Astrorca boss, the penguin, the growing arsenal and its VFX, and the cosmetic skins are a large art surface, so two artists carry it; a single designer owns the roguelite economy (weapons/upgrades/stats), the wave/planet/progression design and the New Game+ tiers (rules: min 1 Design mandated, max 9 total, D+A ≤ 3; see team-formation.pdf). If the economy + wave/tier design outgrows one designer, trade the 2nd artist for a 2nd designer. Scope note (advisory): a novel planet-rotation engine + a 100-enemy ECS + 5 enemies + a boss + 4 planets + an arsenal economy + Firebase + two editors is a very large surface — treat the rotation traversal on one planet, the ECS + ~2–3 enemies, the wave→key→Thingamajig loop and the planet/wave editor as the M1/M2 floor, with the full roster, 4 planets, the arsenal economy and New Game+ as the stretch. The rotation-traversal engine is the highest technical risk — prototype it first.
