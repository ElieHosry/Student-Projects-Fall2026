Subterranean Salvage (student proposal)

Assessment: ✅ Fit · Category: Games · Assessed: 2026-09-21 · Status: awaiting instructor approval

Proposal (as submitted): A collection-based extraction game in a 2D pixel-art style for the web. The player is a treasure hunter sending drones into the Red Zone, evading enemies with heightened hearing by making minimal sound and sneaking, looting homes and chests for items lost to time, and returning to the safe zones before the drone's limited battery runs out. Collected items grant points (rarer = more), and players compete on a leaderboard. Named technical features: a sound-based raycasting system (object interactions produce noise; enemy AI detects and pathfinds to the audio source); a real-time surface lighting system (a cone light dynamically illuminates surroundings when a light source is equipped); a dynamic per-level difficulty framework (positions enemies around high-value loot and key objectives); and an online leaderboard API + cloud database. The load-bearing C++ does real-time acoustic raycasting — radial sound waves on drone noise (fast propulsion, cracking chests) with falloff, obstacle dampening and reflections to alert sound-sensitive enemies. Custom tool: a Red Zone Extraction Level Editor (paint tile layouts, place safe extraction zones, position homes/ruins/loot chests). Design features: environment-driven gameplay; evasion-based extraction (no combat — only outrun/hide/sneak); ≥3 sets of 3 collectable items depicting the past from a post-apocalyptic view; ≥3 enemy zombie types (Normal, Avoidant, Aggressive) with different interactions/stats.

References:

  • Mark of the Ninja — Wikipedia (2D stealth where sounds are shown as expanding circles that alert enemies, with light/dark visibility and a scoring system)
  • Darkwood — Wikipedia (top-down survival where you scavenge/loot and evade enemies drawn by sound and light)
  • Escape from Tarkov — Wikipedia (the extraction genre: scavenge loot in a raid and reach an extraction zone within the time limit or lose it)

How each requirement applies:

Platform fit: Main: Web browser on mobile — the proposal targets web applications (HTML/JS/CSS + the C++ engine compiled to WASM via Emscripten), touch-first on the phone (device: Pixel 9a); the Native PC build is the development/tools & benchmark vehicle. Extended: Firebase + Linux server set up by M2 (full use T2).
Front end: The pixel-art Red Zone renderer (drone, 3 enemy types, homes/ruins/chests, items), the real-time cone-light/surface lighting, sound-visualisation and detection cues, the battery/loot HUD, safe-zone/extraction UI and the leaderboard (OpenGL ES / WebGL). Languages: Web — HTML/JS/CSS + C++→WASM (Emscripten, SDL2/3, OpenGL ES/WebGL). (Web-on-mobile target — no native Android build this trimester; the Native PC build is the dev/tools vehicle.)
Back end: Engine core (fixed-timestep loop, entity system, drone movement & collision, the acoustic raycasting/propagation service, enemy AI & sound-source pathfinding, loot/battery/extraction systems, per-level difficulty placement) + a leaderboard service. Languages: C++.
Backend scope: Local now, server-ready (T2) — leaderboard/cloud DB seam set up & basic-tested by M2, full use in T2.
  • Loop and/or service: the load-bearing C++ is the acoustic raycasting service — on drone noise it casts radial sound waves and computes falloff, obstacle dampening and reflections in real time, feeding sound-sensitive enemy AI that pathfinds to the source; the fixed-timestep loop also advances drone movement, the battery timer, loot and the 3 enemy behaviours.
  • Data-driven: tile layouts, the Red Zone/homes/ruins/chests, the 3 enemy types and stats, the item sets, difficulty rules and acoustic/lighting parameters are all hot-reloadable JSON — no hard-coded levels, enemies or items.
  • 2D: pixel-art sprite/tile rendering of the Red Zone, drone, enemies, items and chests, plus the real-time cone-light/surface lighting and sound-wave visualisation (custom-rendered). 3D: not needed. Networking: async online leaderboard; no real-time netcode.
  • Custom tool: the Red Zone Extraction Level Editor — paint tile layouts, place safe extraction zones and position homes, ruins and loot chests, with live preview.
  • External DB: the cloud leaderboard/high-score database. Auth ⏭️: accounts for leaderboard identity. Analytics ⏭️: optional — where runs fail (detected / battery-out / by which enemy), for difficulty tuning.

M1:

    Tech & dependencies

  • G2 ⭐ Data-Driven Architecture of Core Objects / Entity System
    Tech & dependencies
    • Tech: Entity/component registry in C++ with tiles, the Red Zone/chests/items, the 3 enemy types & stats, difficulty rules and acoustic/lighting parameters in JSON (nlohmann/json) with hot-reload.
    • Prerequisites: G1 (loop & entity update hooks).
    • Feeds into: M2G2 (the level editor edits this data), M1G6/M1G8 (acoustic + enemy data), M2G10 (difficulty placement).
  • G3 ⭐ Debugging, Profiling, Stress Test & CI
    Tech & dependencies
    • Tech: ImGui overlays for sound-wave propagation, enemy alert state and detection, Tracy profiling, Catch2 stress tests (many simultaneous sound sources + enemies), GitHub Actions Windows+Linux matrix.
    • Prerequisites: G1 (loop to instrument).
    • Feeds into: M2G3 (CI hardening) and the WASM frame budget M2G1 validates.
  • G6 Audio System — the acoustic raycasting/propagation service: radial sound waves, falloff, obstacle dampening and reflections that alert enemies.
    Tech & dependencies
    • Tech: A C++ acoustic model casting radial rays on noise events (propulsion, chest-cracking), computing falloff, obstacle dampening and reflections, and emitting alert events to enemy AI; FMOD/OpenAL for the actual SFX playback tied to the same events.
    • Prerequisites: G1 (loop/tick), G2 (acoustic parameters as data).
    • Feeds into: M1G8 (enemies pathfind to the loudest source); the core stealth mechanic.
  • G8 Enemy AI & Pathfinding — hearing-based detection + pathfind-to-sound for the 3 enemy types (Normal, Avoidant, Aggressive).
    Tech & dependencies
    • Tech: A*/flow-field pathfinding to the alerting sound source, steering, and finite-state machines for the 3 enemy types' distinct behaviours/stats (custom C++), tuned from data.
    • Prerequisites: G1 (tick), G2 (enemy data), G6 (sound alerts).
    • Feeds into: M2G10 (advanced behaviour + difficulty placement); the evasion loop.
  • G5 Physics & Collision — drone movement, collision with the environment/chests, and the raycast geometry the acoustic system uses.
    Tech & dependencies
    • Tech: C++ + GLM math, a custom integrator for drone movement, broadphase (uniform grid / quadtree), collision resolution, and ray/segment intersection against walls/obstacles (shared by acoustics and line-of-sight).
    • Prerequisites: G1 (loop & tick).
    • Feeds into: M1G6 (obstacle dampening/reflection geometry); movement feel.

Track Goals & Team Composition

Recommended composition: 6 CS + 1 Design + 2 Art (9) — a 2D pixel-art world (the Red Zone tileset, homes/ruins/chests, the drone, 3 enemy zombie types, ≥9 collectable items and the lighting/VFX) is a big art slot, so 2 artists; a solo designer owns the acoustic-stealth/extraction loop, the level and difficulty design and the item/point economy (rules: min 1 Design mandated, max 9 total, D+A ≤ 3; see team-formation.pdf). If level/content volume grows, trade the 2nd artist for a 2nd designer. Scope note (advisory): acoustic sim + real-time lighting + difficulty framework + editor + 3 enemies + 9 items is a large surface — treat the acoustic-stealth extraction core with 1–2 hand-built Red Zones + the editor as the M1/M2 floor, with the difficulty framework and full item sets as the stretch.
