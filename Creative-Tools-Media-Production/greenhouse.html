Greenhouse - Team18 (student proposal)

Assessment: 🔶 Fit with adjustments · Category: Creative Tools & Media Production · Assessed: 2026-09-21 · Status: awaiting instructor approval

Proposal (as submitted): A journaling app that makes self-reflection more engaging through visual progression and personalization. Each user starts with a unique seed that grows into a garden as they write entries, so they can look back and see their journey — encouraging a journaling habit. A scrapbook feature lets users freely arrange photos, stickers and text to personalize each entry. Named technical features: procedural generation & progress (rule-based plants grown from a user's unique seed; interactions/stats affect base generation and growth; stored as a seed and rebuilt as a mesh on load); a real-time 3D garden renderer for mobile (instanced foliage, simple wind physics as a GPU shader, a cell shader for a 2D-drawn look); a custom scrapbook canvas (drag/pinch/rotate, runtime photo import); and on-device handwriting (velocity stroke smoothing, vector stroke storage for sharp graphics). Load-bearing C++: a fixed-timestep loop for realistic growth over real time, driving physics/animation and real-time gesture→screen interaction. Custom tool: an editor for app-layout editing, plant-generation editing and creating custom graphics/stickers/photos onto a note. Design features: living garden progression, scrapbook-style entries, personalized themes/backgrounds, and a customizable character profile.

Category note: filed under Creative Tools & Media Production — the product is an authoring surface (scrapbook canvas + on-device handwriting + customization), and canvas content comes from users, which is the category's spine. The procedural 3D garden is the standout media/visual feature; runner-up categories would be Games or Immersive Experience (for the 3D garden), but the core loop is creative authoring + journaling, not a game.

Adjustments required for approval:

  • Scope the 3D garden against the 2D gate. The module's 2D output is the hard gate — here it's met by the custom scrapbook canvas + handwriting (custom-rendered in OpenGL ES), which is solid. 3D is "strong students only" / optional, and a real-time 3D renderer on mobile with low-level libraries (OpenGL ES, no engine) is a large risk. Either render the garden as a 2D/2.5D custom-rendered progression (de-risked, still satisfies the gate) or commit to real-time 3D as an explicit strong-student 3D goal with a 2.5D fallback — don't let the 3D renderer starve the core journaling/authoring product.
  • Keep the load-bearing work as the team's own C++. The procedural plant generation, growth simulation, gesture handling and handwriting stroke engine must be the team's own benchmarked C++ (not an off-the-shelf engine), so the project doesn't collapse into ordinary app development. The procedural plant generation + growth simulation is novel for this category's pool — propose it as an instructor-approved new pool goal (see below).
  • Privacy for personal content. Journal text and imported photos are sensitive — keep them local/encrypted with an explicit export, and if any sharing is added later, add moderation. (Minor, since the app is personal.)

References:

  • Day One (dayoneapp.com) — the award-winning journaling app: add photos, drawings and audio to entries and revisit past moments to build a journaling habit
  • Goodnotes (goodnotes.com) — handwriting-first notebooks with stickers, images and freeform pages (the scrapbook canvas + on-device handwriting pillar)

How each requirement applies:

Platform fit: Main: Native mobile + Web browser on mobile — a mobile journaling app with a GPU-rendered garden and on-device handwriting is touch/stylus-first (device: Pixel 9a); the Native PC build is the development/tools & benchmark vehicle. Extended: Firebase + Linux server set up by M2 (full use T2).
Front end: The scrapbook canvas (drag/pinch/rotate composition of photos/stickers/text), the on-device handwriting layer (vector strokes), the garden view (2D/2.5D or 3D per adjustment 1), themes/customization and the character profile (OpenGL ES / WebGL for the custom canvas + garden). Languages: Web — HTML/JS/CSS + C++→WASM (Emscripten, SDL2/3, OpenGL ES); Native — Kotlin Native Android UI + C++ via JNI (Android Studio); OpenGL ES in a GLSurfaceView where realtime 2D/2.5D is needed (no SDL on native).
Back end: Engine core (fixed-timestep loop, document/journal model, procedural plant generation + growth simulation, gesture processing, the handwriting stroke engine, and the garden renderer) + a cloud save / asset-library service. Languages: C++.
Backend scope: Local now, server-ready (T2) — cloud save/library seam set up & basic-tested by M2, full use in T2.
  • Loop and/or service: the load-bearing C++ is a fixed-timestep engine that advances plant growth against real elapsed time (seed → generated plant → growth), processes gestures (drag/pinch/rotate) into canvas transforms in real time, smooths handwriting strokes by velocity, and drives the garden animation.
  • Data-driven: the journal/document model, plant generation rules, the seed and growth stats, themes/backgrounds, sticker sets and the character are all hot-reloadable JSON — the editor tunes plant generation and layout without recompiling.
  • 2D: the scrapbook canvas (custom composition/transform rendering) and the handwriting (vector stroke rendering) are custom-rendered in OpenGL ES — this satisfies the 2D gate. 3D: the garden is optional/strong-student (see adjustment 1). Networking: cloud save/sync only; no real-time collaboration.
  • Custom tool: the editor — app-layout editing, plant-generation editing (tune rules and watch plants regenerate), and authoring custom graphics/stickers for notes, with live preview.
  • External DB: cloud save/backup of journals, the garden seed and the sticker/asset library. Auth ⏭️: accounts for cloud save + profile. Analytics ⏭️: optional — journaling-habit retention.
